Overview

Abstract

In human-robot interaction, agentic robots should resolve ambiguous user requests through proactive clarification while keeping user burden low. We study this challenge in interactive instance navigation, where an agent must identify and reach the user-intended target among similar objects. Existing approaches ask open-ended questions and select a candidate that strongly matches the accumulated user-provided information. However, this process can require lengthy user responses and lead the agent to make premature decisions without distinguishing the target from distractors.

To address these limitations, we propose Proactive Instance Navigation with Comparative Judgment (ProCompNav), a two-stage framework that first constructs a candidate pool and then identifies the target through Recursive Comparative Judgment (RCJ). RCJ iteratively narrows the pool by selecting an attribute-value pair that divides the candidates, asking the user a binary question, and removing inconsistent candidates, without requiring an attribute unique to the target.

ProCompNav substantially improves Success Rate and reduces Response Length on an interactive navigation benchmark, and achieves the highest Success Rate among evaluated methods on a non-interactive benchmark. In two human studies, participants preferred ProCompNav’s binary questions to open-ended questions and its batched delivery to interleaved interaction. Our results highlight the need to jointly consider task performance and user-friendly interaction strategies when designing agentic robots.

Method

Collect first, then compare

  1. STAGE 1

    Pool construction

    Explore before deciding. Every object of the requested category becomes a candidate.

  2. STAGE 2

    Recursive Comparative Judgment

    Ask one yes/no question about an attribute that splits the candidates, and keep the side that fits. Repeat until one is left.

  • Easier for the robot

    Find one difference among the candidates, instead of matching each one to a vague target.

  • Easier for the user

    Answer yes or no, asked once after collecting.

Comparison

Three strategies for ambiguous instance navigation

  • PRIOR WORK

    Independent matching

    Asks open-ended questions and checks each candidate alone. Long answers, and it can stop at a look-alike.

  • NATURAL FIX

    Pooled independent matching

    Collects candidates first, but still checks each one alone. Answers get even longer.

  • OURS

    Comparative judgment

    Collects first, then asks yes/no questions that split the candidates.

Same candidate pool, different questions: comparing raises success and cuts the user’s answers from hundreds of tokens to about four.
